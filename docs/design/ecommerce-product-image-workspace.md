# 电商产品图工作空间规划

## 版本边界

电商产品生图先在 SonnetArt 社区版实现，用来验证轻量工作流和用户体验。Cosmos 是商业化版本，后续可以在这个基础上增强团队资产、平台规则、批量运营、商品库复用和更完整的导出管理。

SonnetArt 当前已有两类工作区：

- `graphic`：作图空间，负责文生图、图生图、编辑、变化、扩图、Gallery 和矩阵生成。
- `copy`：文案空间，负责文本对话和文案生成。

建议新增第三类工作区：

```text
commerce-product-image
```

社区版首期目标不是做重型 PIM 或平台运营系统，而是把一件商品从“信息与参考图”推进到“一套可评审、可迭代、可导出的商品图”。

## 图中流程拆解

### 1. 导入产品信息

输入来源：

- 商品链接
- 产品描述
- 上传图片
- SKU 或颜色信息

SonnetArt 首期建议：

- 先支持手动录入商品名称、描述、卖点、规格、目标人群。
- 先支持上传产品参考图，并默认设置为 `product` 参考图角色。
- 商品链接抓取放到后续阶段，避免社区版被站点差异、反爬和版权问题拖住。

### 2. AI 分析产品

识别维度：

- 产品类型
- 核心卖点
- 适用场景
- 颜色变体
- 材质特性
- 目标人群

输出形态：

- 结构化商品事实
- 可编辑的识别结果
- 用于提示词的商品事实摘要
- 风险提示，例如品牌露出、文字误生成、材质不确定、尺寸缺失

这里的商品事实是后续所有图片节点的共同来源，不直接等同于某张图的提示词。

### 3. AI 规划图片方案

图中图片类型可以抽象成节点：

- 主图：白底、情境、平台首图
- 场景图：健身房、户外徒步、办公室、家居等
- 细节图：防漏设计、材质展示、容量刻度、握持结构
- 对比图：与普通产品对比、效果对比、尺寸对比
- 尺寸图：尺寸标注、容量说明、包装规格
- A+ 图：品牌故事、卖点长图、详情页模块
- 包装图：包装展示、套装组合、赠品组合

每个节点应包含：

- 图片目标
- 画幅和尺寸
- 参考图角色
- 商品事实引用
- 场景、构图、灯光、风格约束
- 负面约束
- 计划生成数量
- 当前状态

### 4. 用户确认与编辑规划

图中最关键的是中间的可视化规划区：商品主体在中心，向外分出主图、场景图、细节图、对比图、尺寸图等分支。

SonnetArt 首期可以采用稳定三栏，而不是马上做自由画布：

- 左栏：商品与批次列表。
- 中间：图片规划树和节点详情。
- 右栏：当前节点结果、版本、创意迭代和导出操作。

后续再升级为脑图式节点画布。

### 5. 批量生成首轮方案

每个节点可以生成多种方案：

- 健身房场景生成 4 种构图
- 户外徒步场景生成 3 种构图
- 细节图每个卖点生成 2 个版本
- 主图生成白底、浅灰背景、轻场景三类

生成结果需要保存：

- 来源商品
- 来源节点
- Prompt
- 模型、尺寸、质量、格式
- 参考图数量和角色
- 生成耗时和成本估算
- 版本号
- 评审状态

这部分应尽量复用现有 `ImageGenerationClient`、`GeneratedImage` 元数据、Gallery 和矩阵生成逻辑。

### 6. 创意分叉迭代

图中的“创意分叉迭代”表示从任意首轮图继续派生风格版本：

- 增强光影
- 欧美风格
- 高级质感
- 电影氛围
- 更强电商点击率
- 更适合详情页说明

数据层建议：

- 商品图节点是规划层。
- 生成结果是版本层。
- 创意迭代是从某个版本创建子版本。
- 用户可以把任意子版本设为母版。

### 7. 应用所有变体

图中以红色、绿色、黑色、白色水杯为例，表示在已确认母版上批量套用 SKU 变体。

变体维度：

- 颜色
- 材质
- 尺寸
- 套装
- Logo 或无 Logo
- 背景色
- 平台比例

关键原则：

- 变体不重新规划整套图片，而是复用已确认母版构图和节点。
- 商品主体一致性优先使用原始产品图或确认母版作为参考。
- 变体任务应能一次应用到所有选定节点。

### 8. 导出与管理

图中导出目标包括 Amazon、Ozon、Mercado Libre、Shopee、Shopify 和独立站。

SonnetArt 社区版首期可以做轻量导出：

- 批量下载
- 按商品/SKU/节点分文件夹
- 分辨率选择
- 文件命名规则
- 图片清单 JSON

平台规则校验和更完整的运营导出适合放到 Cosmos 商业版。

## 本地工作空间布局

### 左栏：商品与批次

- 商品列表
- 批次列表
- SKU/颜色变体
- 导入入口
- 当前商品识别摘要

### 中间：规划树与节点工作台

- 商品中心信息
- 主图、场景图、细节图、对比图、尺寸图、A+ 图节点
- 节点状态：待规划、待确认、待生成、生成中、待评审、已确认、需重绘、已导出
- 节点详情编辑
- 批量生成操作

### 右栏：结果、迭代与导出

- 当前节点结果网格
- 版本历史
- 创意迭代按钮
- 变体套用矩阵
- 导出预设
- 下载/导出

## 建议数据模型

新增或扩展模型：

- `CommerceWorkspaceState`
- `CommerceProduct`
- `CommerceProductFact`
- `CommerceSkuVariant`
- `CommerceImagePlan`
- `CommerceImageNode`
- `CommerceImagePrompt`
- `CommerceGeneratedAsset`
- `CommerceCreativeBranch`
- `CommerceExportProfile`
- `CommerceExportJob`

与现有模型关系：

- `StudioWorkspace` 增加 `CommerceType` 和 `CommerceWorkspace` 状态。
- `CommerceGeneratedAsset` 可持有或映射到现有 `GeneratedImage`。
- 图片生成仍通过 `StudioImageRequest` 和 `ImageGenerationClient`。
- Gallery 可以增加电商工作区过滤，也可以首期先只在节点内展示结果。

## 实现路线图

### P0：工作区骨架和状态

- 新增 `StudioWorkspace.CommerceType = "commerce-product-image"`。
- 扩展 `StudioWorkspace.NormalizeType`、`DefaultName`、`CreateDefaultSession`。
- 扩展 `WorkspaceCreateDialog`，新增“电商产品图”选项。
- 扩展首页工作区判断：`IsCommerceWorkspace`。
- 首期先显示电商空状态和三栏布局占位。
- 新增 `CommerceWorkspaceState` 并挂到 `StudioWorkspace`，保证本地持久化。

验收标准：

- 用户可以创建“电商产品图”工作空间。
- 刷新后工作区类型和基础状态不丢失。
- 不影响现有作图空间和文案空间。

### P1：商品档案

- 商品名称、描述、卖点、规格、目标人群。
- 颜色/SKU 变体维护。
- 产品参考图上传，并默认使用 `product` 参考图角色。
- 商品档案列表和当前商品切换。

验收标准：

- 一个工作区可以保存多个商品。
- 每个商品可以保存参考图和 SKU 变体。
- 商品档案可以作为后续生成的上下文。

### P2：AI 商品分析

- 调用 `PromptChatClient` 生成商品事实。
- 输出产品类型、卖点、场景、颜色、材质、人群。
- 结果可编辑、可重跑、可保存。

验收标准：

- 用户输入商品资料后可生成结构化商品事实。
- 用户修改后，规划节点使用修改后的事实。

### P3：图片规划树

- 根据商品事实生成节点树。
- 内置节点类型：主图、场景图、细节图、对比图、尺寸图、A+ 图、包装图。
- 节点支持新增、删除、排序、启用/停用。
- 每个节点生成初始提示词和负面约束。

验收标准：

- 商品能自动生成一套可编辑图片规划树。
- 用户能调整节点和提示词。
- 节点状态完整可见。

### P4：节点生成和评审

- 节点级批量生成。
- 每节点多方案生成。
- 结果绑定到商品、节点和版本。
- 支持设为母版、收藏、重绘、继续编辑。

验收标准：

- 用户能一次生成一组首轮商品图。
- 每张图能追溯来源节点和参数。
- 已确认图片能作为后续变体母版。

### P5：创意迭代与变体套用

- 从已生成图片创建创意分支。
- 内置迭代方向：光影、质感、平台点击率、生活方式、详情页表达。
- 支持颜色和 SKU 变体矩阵。
- 支持把已确认母版批量应用到多个变体。

验收标准：

- 用户能从一个方案派生多个创意版本。
- 用户能把颜色变体套到已确认构图。
- 变体生成结果按 SKU 归档。

### P6：轻量导出

- 内置导出预设：Amazon、Ozon、Mercado Libre、Shopee、Shopify、独立站。
- 按预设生成尺寸、比例、格式和命名规则。
- 导出 ZIP，包含图片和 JSON 清单。

验收标准：

- 用户能按商品、SKU、节点和平台预设导出。
- 导出包包含可复查的生成参数。

## 首期建议范围

第一版只做闭环，不做重型平台功能：

```text
创建电商工作区
-> 新增商品
-> 填产品信息和上传参考图
-> AI 生成商品事实
-> AI 生成图片规划树
-> 用户确认节点
-> 选择节点批量生成
-> 结果设为母版
```

商品链接抓取、平台规则校验、复杂导出、团队模板和跨商品资产库放到后续。

## 风险和待确认

- 商品链接抓取涉及站点差异、反爬和图片版权，社区版首期应延后。
- 产品主体一致性是核心体验，需要优先测试 `product` 参考图角色和提示词模板。
- 颜色变体可能需要更强的局部编辑或参考图约束，否则容易改变商品结构。
- A+ 图常包含文字，图像模型文字稳定性不足，首期应以少字详情模块为主。
- 平台规则会变化，完整校验更适合放到 Cosmos 商业化版本。
